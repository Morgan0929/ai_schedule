# 日程数据的身份认证与归属校验

日程、课表、附件、Agent 对话与历史、待办和课表导入接口使用
`common.utils.authentication` 中的共享 FastAPI 依赖。

## 请求流程

1. 客户端通过 `Authorization: Bearer <JWT>` 提交令牌。
2. 服务端验证 JWT 的签名和有效期，读取 `sub`（用户 ID）与 `sid`（登录会话 ID）。
3. 查询 Redis 登录会话，检查会话存在、会话 ID 与用户 ID 匹配，且会话中的用户处于启用状态。
4. 业务接口使用服务端确定的用户 ID。旧客户端可以继续提交自己的 `user_id`；如果提交其他用户 ID，返回 403。
5. 列表查询按用户 ID 过滤；单条资源的读写和附件操作校验记录归属。其他用户的记录返回 404。

登录会话 ID 用于验证登录状态；日程表中的用户 ID 用于判断数据归属。
两者不是同一个字段。退出登录删除 Redis 会话后，上述受保护接口不再接受对应的旧 JWT。
Redis 无法完成会话检查时，请求不能仅凭 JWT 获得访问权限。

Agent 对话的会话 ID 另有用途：区分对话。外部提供的对话 ID 按认证用户增加
`u<user_id>:` 前缀，已带其他用户前缀的 ID 会被拒绝，防止读取或沿用其他用户的工作记忆。
历史查询同时限制数据库记录中的用户 ID。旧的不带用户前缀的对话 ID 会被映射到新的用户命名空间。

## 图片与客户端兼容

`/media/{kind}/{filename}` 通过鉴权路由读取，不再公开挂载上传目录。
图片请求需要 JWT，并检查所属日程和附件记录。返回 `Cache-Control: private, no-store`。
手机端普通、上传和流式请求原本已携带 JWT；任务和课程卡片的图片请求现已补充认证头，
且只向配置的图片服务同源地址发送令牌。

## 验证

从项目根目录运行：

```powershell
./venv/Scripts/python.exe -m unittest discover -s backend/tests
```

`test_user_authorization.py` 使用隔离的内存 SQLite 数据库与模拟 Redis，
验证双用户 CRUD、冒用用户 ID、重复查询参数、无登录请求、过期令牌、会话撤销、
Agent 身份与会话隔离、课表导入和私有图片访问。这些是本地 HTTP 回归测试，
不代表线上 PostgreSQL、Redis 或手机端实机验收。

## 面试回答

我把身份认证和资源授权分开处理。请求先通过 JWT 签名、有效期以及 Redis 登录会话校验，
由后端确定当前用户 ID，而不是直接相信前端传来的用户 ID。
查询日程列表时按用户 ID 过滤；读取、修改、删除单条日程及访问附件时，校验记录归属，
非本人的记录返回 404。Agent 和课表导入使用同一套身份认证，避免绕过日程接口。
我用两个用户做了 HTTP 回归测试，验证修改日程 ID 或冒用用户 ID 都不能访问他人数据。
